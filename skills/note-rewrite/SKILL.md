# 洗稿

## 最新执行标准 2026-10-13

用户已否定“原图只微调构图”的旧执行方式。**保留的是内容逻辑、叙事套路和原图的传播表达。** 2026-10-13同轮补充：原图是普通表情包，就保留表情包的直给表达；原图是操作截图，就沿用简洁截图讲解。可选择人物、软件/具体案例、背景、上下/左右布局等一两个方向做实质改写，不强制每个元素全换。真实操作界面是允许复用的局部，不能因此把整个海报原样复制。换背景本身可以作为一个方向；验收看是否形成明显新画面，不能只有图标微移、小边框或难以察觉的色差。

百度搭子内容先读[2026-10-13审核规范](references/review-20261013.md)：中文品牌名、品牌与生成成果的归属关系、提示词生成工作台的表达是本轮新增必查项。后续用户明确保留某个元素时，仅锁定该元素，不把局部保护扩大为整页保留。

同日追加的四条产品门槛必须落实到实际交付：百度搭子没有skill商店，不保留旧技能/套件入口引导；新图文品牌只用中文，截图角落和输入框也要查；每篇有可读提示词或完整步骤，正文内可复制，不暗示打开产品即有展示成果；玄学从个人用材料和提示词搭建工作台切入，成果内部也不能残留确定性解读。详见本skill内附审核规范；已安装搭子skill时同时读取其“最新审核门槛”。通知更新时复核当批所有A/B版、预览和ZIP，不能仅更新规范后继续交付旧图。

**两篇或多个版本的表现不同，但核心内容完全相同。**

先理解原文希望读者记住什么，再用新的叙述角度、句式、结构、例子和图片表现把同一个意思讲出来。核心表达、关键功能、条件、过程、成果和收益保持完整一致；文案和视觉形式都可修改。图片以原图为临摹参考，可替换主体、背景，也可修改配色、构图、排版、信息层级和元素位置。临摹的依据是原图要传达的核心内容与展示逻辑，不要求视觉形式逐项相同。

例如，原文的核心是“百度搭子根据天气教你穿搭”。不同版本可以重写穿搭建议，换整套衣物、鞋包配件、背景及卡片构图排版，仍完整讲“搭子根据天气教你穿搭”。关键锚点保留的是功能含义，锚点对应的具体表现对象可以替换；其他主题按其自身对象处理，不把每篇换衣服写成通用要求。

## 同轮补充：保留原图网感，控制修改变量

用户以唐僧PPT表情包明确纠正：可以换办公软件、换人物表情包、换背景或把上下改为左右，功能卖点仍然是“搭子可以帮我干这件事”。**改写不等于整套重新美术设计，更不等于加重AI味。**

先写清原图有效的表达语法（如大字＋两种表情＋前后反差），再选1—2个有实质差异的变量。保留其简单、直接、普通用户能制作的质感。禁用默认的虚拟精致人物、3D吉祥物、摄影棚办公室、满屏贴纸、手账道具和无必要的文案层。AI工具只完成选定编辑，不自由升级成宣传海报。

换软件或具体案例时，同步改输入、输出、截图和正文；不能只把PPT图标换Excel却仍展示PPT。未换任务时继续用原任务真实UI。首轮先看封面和含真实UI的内页各一张，核对网感、卖点和界面，再批量扩展；不让错误方向一次扩散几十张。用户指出AI味重时先停当前批次，修生产提示词和成图。

## 使用范围与资料

用户要求“洗稿、照这篇改写、同样内容换表达、参考做几篇、除关键锚点外都换一次”时使用。用户只要求总结流程或修改 skill 时，交付相应文档或 skill；要求成品时完成指定的文字或图文。

优先使用用户指定的参考。读原文和全部配图，拟用界面看原尺寸；缺少原文或图片时先查现有项目素材，再补充必要材料。不要只读摘要就声称看完原稿，也不为一次指定参考改写额外搜集大量无关样本。

本 skill 可独立用于文章和图文改写。制作百度搭子笔记时，先读内附审核规范；若当前环境已安装 `$dazi-note-studio`，读取其入口并使用适用的品牌、界面素材、产品事实和审核规范。未安装时使用用户提供的准确资料，不依赖仓库外的相对路径，也不编造产品界面。本 skill 负责确定改写范围与保证核心表达不变；其他主题按各自素材和规范执行。

## 制作流程

### 1. 拆清原文核心

用一句话写清原文的核心表达，再列出关键锚点：主旨、产品/品牌、主要功能、必要条件、关键步骤、成果类型和读者收益。区分锚点的功能含义与具体表现对象：功能含义保留，具体对象、文字措辞、示意例子和图片形式可以改。每个新版本都覆盖同一份核心内容清单。

如果原文同时介绍定时任务、天气检索和可视化穿搭报告，新稿仍要完整传达这些内容，不能只留下“搭子会穿搭”一句泛化卖点。

### 2. 列保留与替换清单

逐页写清“真实操作界面保留区域”和“实际替换的视觉元素”。制作前把两个版本并列比较：同一逻辑能否用不同的人物/对象、字体、配色、道具和成果呈现讲出来。遇到独立第三方App素材，先确认它与主推品牌的关系；来源没有该关系时，改用同功能且有依据的搭子生成案例，不凭空给原App改归属。

制作前分别记录文字与图片的保留、替换范围：

| 层次 | 处理方式 |
| --- | --- |
| 核心表达与关键锚点 | 含义保留，可换说法和出现顺序；不改变主推功能、关键条件或结论 |
| 文字表达与具体例子 | 重写标题、开头、叙述角度、段落组织、图内文案和例子，完整传达同样的核心内容 |
| 图片表现形式 | 以原图为临摹参考，围绕关键锚点替换主体、背景；配色、构图、排版、元素位置和信息层级均可修改，核心内容与成果含义保持一致 |
| 用户指定保留的内容及真实事实 | 按指定范围保留；真实数据、实测结果、引用结论不为制造差异而改造 |

按“核心内容完全相同、表现形式不同”执行，不把原构图、排版或局部替换位置锁成默认限制。用户明确指定不动的截图、数据、主体或布局按指定范围保护；后续明确调整时以最新要求更新清单。只修改skill时不重新生成图片；用户要求返修成品时再同步修图。

### 3. 设计每篇新的表达方案

为每篇确定如何重新讲述同一个核心：从什么角度开场、信息按什么顺序展开、用哪些具体例子、替换哪些主体和背景、怎样通过构图和排版展示相同的功能与成果。

人物、痛点、地点、作息可在有助于表达时调整，**不要求每篇重新设定这些条件，不强制转成另一个场景或换掉文章主题。** 同批版本通过文案组织、具体对象、主体、背景、配色或构图排版形成明确的表现差异，每篇核心内容完全相同。不将逐句换同义词或只改标题作为完成标准。

替换对象按任务处理。例如穿搭换整套衣物及对应鞋包配件，旅行换景点或路线示例，资料整理换示意材料；主体、背景和展示版式可一起调整。用户锁定原主体时保留该主体，调整其他允许修改的表现形式。

记录该篇实际采用的条件、对象和参数，供输入、对话、结果、图片和正文共同使用。无需改变的参数不为了差异强行替换。

### 4. 重写文案、指令和对应成果

围绕保留的核心重新组织标题、正文、图内文字和相关话题，从新的表达方案写起。重新安排论述顺序和具体动作，避免沿原文逐句替换。删去空泛夸赞和制作口吻，保持自然的使用者表达。

涉及工具操作时，写出可读、可复制的用户指令，再准备对应的可见成果。改过的条件贯穿任务名、输入、对话、文件名、输出卡、预览及正文；只需修改与该条件有关的内容。

根据新表达方案安排分镜、信息顺序和图文布局，可重新组织原参考的内容。保留原文的重要功能、过程与收益，不能因重排、缩短或换图漏掉关键锚点。

### 5. 参考原图重做视觉，核心内容保持完全一致

将相关原图作为图像生成/编辑参考，用AI临摹其内容和功能展示，并按该篇方案修改主体、背景、配色、构图、排版、元素位置与信息层级。原参考展示了哪些功能、步骤与成果，新图仍完整表达这些内容；具体衣物、人物或其他表现对象可以替换。

逐图提示词明确写出：参考哪些原图、必须保留的核心内容与关键锚点、替换什么主体与背景、采用什么配色和构图排版、哪些文字与参数要同步。允许表现方式变化，逐项核对核心含义和成果完整性，不把“图片看起来一样”当作验收标准。

原搭子界面可以复用。产品品牌、控件和布局有真实素材依据；其中需要改写的场景文字和结果按本篇条件同步调整。默认无需每篇重新登录运行任务，用户要求实测时再实际操作。

长中文、品牌、数字和密集图表逐字核对；必要时保真贴图或准确排字。图像编辑遵循当前工具规则，需要程序合成时使用已有适用授权；不能自行以程序重绘替代默认图像编辑工具。

同篇主体、对象和参数一致，篇内视觉协调；同批各篇表现有区别，核心内容完全相同。保留原素材；记录实际生图提示词、素材来源、核心内容对应关系、主体背景替换及构图排版方案。复用同一素材制作多个页面时，不把这些页面记为多次独立生图调用。

### 6. 检查核心、改写范围和前后一致性

先做图片差异验收：遮住真实操作界面区域后，把原图、A版和B版并排看；应一眼看出是新制作的图片。若仍像同一张图、只有位移/边框/小装饰变化，直接返修。每张最终页都要有实际重做记录，不能用整页原图或同一页截图凑两个版本。文字密集时只保护/复用对应截图局部，重做外围构图与内容；保真困难不能成为整页照搬的默认理由。

对照原稿与最终成品检查：

- 原稿与各新版本的核心内容是否完全相同，关键功能、条件、过程、成果和收益是否逐项完整，是否被误改或遗漏。
- 应替换的文字和例子是否已重写；改过的城市、姓名、日期、服装、文件等是否还有旧内容残留。
- 输入、指令、对话、成果、图表和正文是否属于同一篇任务；数值、对象和建议是否相互对应。
- 文案与图片是否已形成不同表现，主体、背景、构图或排版等是否按方案修改；变化后是否仍准确传达同一核心内容。
- 图片是否有乱码、遮挡、拉伸、糊小字或品牌错误；提示词与成果是否清楚可读。
- 控件是否都有真实素材依据；小标题与说明是否对应；分项与合计是否一致；替换后的地点、对象和成果是否还有旧文案。幕后制作指令不得出现在成图中。

逐图看原尺寸，再看手机阅读尺寸和整组预览。文字检索辅助检查，不替代看图。发现问题修最终文字或图片，不能只改提示词或补解释。

产品事实复核须覆盖图内小字：旧侧栏、输入占位提示、加载状态、英文Logo及生成工作台里的内容。OCR搜词后人工判断整篇是否讲清输入到结果，不把“未命中禁词”当作语义通过。图像返修后重新目检，最终包的图片和文案逐文件对比核验版哈希；不合格图不得靠改名或换回原图混入ZIP。

内部区分原始截图、AI 场景、示意成果和本次实测；合成内容不记录为原始截图或实际运行结果。示意数据可随示意场景调整，真实引用内容保持准确。

### 7. 交付和记录

2026-10-13用户明确：最终ZIP只保留“笔记主题/第一篇、第二篇”，每篇文件夹内放“笔记.txt”（标题、正文、话题）与有序图片。预览、原文、提示词、反馈、技能和制作记录留在项目内部，不放入最终交付包；主题单独包使用同样结构。

这里的“提示词单独留存”指内部独立文件；给读者使用的提示词仍须写进笔记正文或图中，不能因精简ZIP而漏掉操作引导。

按用户范围交付。纯文字任务给完整新稿；图文任务默认交付有序图片、标题/正文/话题、可复制用户指令、整组预览和 ZIP。尺寸与页数按用户要求；未指定时结合参考与内容选择，分镜和顺序可重新组织。

保存原参考、保留/替换清单、各篇表达方案、准确内容与参数、实际生图提示词、来源和修正记录。检查文件数量、预览引用和 ZIP 完整性。原稿和旧版保留；发布或外部同步按当轮授权执行。
